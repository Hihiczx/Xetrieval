Embedding-level mechanistic interpretability for dense retrieval

Xetrieval: Mechanistically Explaining Dense Retrieval

Xetrieval explains why dense retrievers assign high relevance scores by identifying sparse, human-interpretable features shared by a query and its retrieved documents.

View Code Get Started

Motivation

Opening the black box of dense retrieval

Dense retrievers compute relevance through high-dimensional query and document embeddings, which makes individual retrieval decisions hard to diagnose. Existing explanations often rely on lexical matches, token alignments, or post-hoc textual rationales, leaving the latent embedding factors underexplored.

What Xetrieval returns

For each query-document pair, Xetrieval returns the shared active features O(q,d) that connect both sides in a sparse mechanistic feature space.

Method Overview

Reasoning-aware sparse feature explanations

1

Encode

Encode the query and document with an e5-style embedding model.

2

Internalize

Approximate Chain-of-Thought reasoning directly in embedding space.

3

Decompose

Apply a TopK-SAE mechanistic explainer to produce sparse features.

4

Explain

Aggregate shared active features across document-side views.

Embedding-level

Explains dense retrieval where relevance scores are actually computed: in the embedding space.

Reasoning-aware

Uses lightweight reasoning internalizers for document-side views such as qa, summary, and purpose.

Feature-level

Reports interpretable sparse features and optional natural-language feature hypotheses for each retrieval decision.

Usage

Run Xetrieval with released checkpoints

The open-source release includes inference code for feature-level retrieval explanation, a TopK-SAE mechanistic explainer checkpoint, and reasoning internalizer checkpoints for three document-side views. 

git clone https://github.com/Hihiczx/Xetrieval.git
cd Xetrieval
pip install -r requirements.txt

python explain_retrieval.py \
  --input_jsonl examples/query_doc_pairs.jsonl \
  --output_jsonl outputs/explanations.jsonl \
  --embedding_model_name intfloat/e5-large-v2 \
  --reasoning_internalizer_dir checkpoints/reasoning_internalizer \
  --mechanistic_explainer_checkpoint checkpoints/sae_model.pt \
  --device cuda \
  --batch_size 64
